## (1) What it actually takes for a non-technical business user to use a Claude Skill or a ChatGPT GPT

**Claude Skills — what the primary docs say.**

A Skill is a folder containing a `SKILL.md` file (YAML frontmatter with `name` ≤64 chars and `description` ≤1024 chars, plus a Markdown body) and optional reference files and scripts. It is zipped with the skill folder at the root of the archive, and the total must be under 30 MB uncompressed. [VERIFIED — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview), [Skills API guide](https://platform.claude.com/docs/en/api/skills-guide), [Creating custom Skills](https://support.claude.com/en/articles/12512198-creating-custom-skills)]

Skills do not run on prompting alone: they run inside Claude's code-execution VM. On the API that means the `code_execution` tool plus the beta header `skills-2025-10-02`; on claude.ai it means the "create and edit files / code execution" capability must be switched on. [VERIFIED — overview + skills-guide + [Use skills in Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude)]

Plan requirements are the first place the sources disagree, and the disagreement matters. Anthropic's developer docs state that custom Skills on claude.ai are "available on Pro, Max, Team, and Enterprise plans with code execution enabled" — i.e. **not Free**. The Help Centre article says "Skills are available for users on Free, Pro, Max, Team, and Enterprise plans," and describes Free/Pro/Max users enabling example skills and uploading their own. [CONFLICT — both cited above.] The likely reconciliation is that Anthropic's four pre-built document Skills reach Free, while *uploading a custom Skill* is a paid feature; but until Sol tests it on a fresh Free account, plan the business on the conservative reading: **the buyer needs a paid Claude subscription.**

Then the institutional gates. On **Team**, skills are on by default at org level; on **Enterprise**, an owner must first enable *both* code execution/file creation *and* Skills in Organization settings. [VERIFIED — Help Centre]. So for a buyer inside any company of size, adoption requires an IT/admin action the buyer cannot take alone — which is exactly the approval step the price band exists to avoid.

Third-party distribution is technically possible and organisationally hostile. Anthropic explicitly supports uploading a ZIP the buyer received, and there is no technical block on Sol shipping one. But: custom Skills **do not sync across surfaces** (a claude.ai skill is not available in the API and vice versa; Claude Code skills are filesystem-only), on claude.ai they are **per individual user** with "no centralized admin management or org-wide distribution," and — decisively for outbound sales — Anthropic's own documentation tells the buyer: *"Use Skills only from trusted sources: those you created yourself or obtained from Anthropic,"* with a warning box about auditing every bundled script for data exfiltration. [VERIFIED — overview §Security; the Help Centre repeats "Only install skills from trusted sources."] A cold-emailed ZIP from an unknown Brazilian vendor is precisely what that sentence is written to stop. That is not a marketing objection Sol can out-write; it is the platform's stated posture.

**Commercial resale.** Anthropic's Consumer Terms assign Outputs to the user and confirm the user retains rights to their Inputs, while prohibiting using the Services to "resell the Services" or to build competing services. [VERIFIED — [Consumer Terms](https://www.anthropic.com/legal/consumer-terms)] A Skill Sol authors is her own content, not Anthropic's service, so selling it is not "reselling the Services" on any natural reading — but **no Anthropic document I could find explicitly permits or governs commercial resale of Skills. Mark that UNKNOWN, not permitted-by-implication.** One hard constraint is verified: in `anthropics/skills`, most skills are Apache-2.0 but the `docx`, `pdf`, `pptx`, `xlsx` document skills are **source-available, not open source** [VERIFIED — [anthropics/skills](https://github.com/anthropics/skills)], so those cannot be bundled into a paid product.

**A warning about a claim you will encounter.** Several SEO pages assert Anthropic launched a public "Skills Marketplace" on 1 May 2026 with ~600 skills, paid skills, and a 15% cut ([500k.io](https://500k.io/journal/anthropic-skills-marketplace-launch), [claudeskillsmarket.com](https://www.claudeskillsmarket.com/)). `marketplace.anthropic.com` **does not resolve** (DNS failure) and I found no primary Anthropic source. What does exist is [`anthropics/claude-plugins-official`](https://github.com/anthropics/claude-plugins-official) — an Anthropic-managed *Claude Code plugin* directory, Apache-2.0, accepting third-party submissions via a form, **with no mention of paid skills**. [VERIFIED] Treat the paid-marketplace-with-revenue-share story as UNVERIFIED and do not build economics on it.

**ChatGPT custom GPTs and Projects.** `help.openai.com` returned HTTP 403 to every fetch, so everything here is **PLAUSIBLE (secondary sources only)**, not verified: creating a custom GPT requires Plus/Pro/Business — Free and the $8 Go tier cannot create them, though Free users can *run* GPTs from the store ([IntuitionLabs](https://intuitionlabs.ai/articles/chatgpt-plans-comparison), [GPT Store — Wikipedia](https://en.wikipedia.org/wiki/GPT_Store)); a GPT is shared by workspace, by link, or by publishing to the store — there is **no export format**, so a GPT cannot be sold and handed over as a file, and a published GPT remains under the builder's account, meaning Sol could not ship the buyer something the buyer owns and controls ([Sharing and publishing GPTs](https://help.openai.com/en/articles/8798878-building-and-publishing-a-gpt), [community thread](https://community.openai.com/t/share-customgpts-to-user/1352332)). Projects are available on Free and paid tiers and accept custom instructions plus attached files — so the *lowest-friction AI-native delivery is a plain .md/.txt the buyer pastes into a project* — but that is a prompt file, which fails R3 outright.

## (2) Alternative delivery formats, ranked by how little the buyer must understand

1. **Template/source pack for software they already own** (Illustrator `.ai`, DXF-AAMA, CLO3D, `.xlsx`, InDesign). Setup: zero — double-click. No account, no runtime, no admin rights, no AI literacy. Highest adoption ceiling of any format.
2. **PDF/checklist system + `.xlsx` with formulas only (no macros).** Under 10 minutes. Works on Windows, Mac, web Excel, Google Sheets (with degradation).
3. **Single-file browser tool the buyer opens locally** (one self-contained `.html`, all CSS/JS/libraries inlined, files chosen via the file picker and processed in-page). No install, no admin rights, no runtime, no network, no AI account; confidential pre-print artwork never leaves the machine. Two engineering constraints, both PLAUSIBLE-known rather than doc-verified: over `file://` you must use a single inline classic `<script>` (ES modules and separate `.js` files are blocked by CORS in Chrome and Safari), and PDF parsing must be a bundled library (pdf.js) rather than a fetch. Expect one "it doesn't open" support email per N buyers; budget a plain-language fallback page.
4. **Spreadsheet + separate script.** Dies for this buyer: Python/Node install, PATH, often admin rights.
5. **Spreadsheet with macros — effectively dead.** Microsoft blocks VBA macros in Office files obtained from the internet **by default** (Current Channel v2206, July 2022 onward; Windows only; Excel/Word/PowerPoint et al.), showing a SECURITY RISK banner with **no "Enable content" button**; the buyer must open file Properties → Unblock, or an admin must add a trusted location or trust a code-signing certificate. [VERIFIED — [Microsoft Learn](https://learn.microsoft.com/en-us/deployoffice/security/internet-macros-blocked)] Do not ship a macro-enabled workbook as a paid downloadable.
6. **Local desktop/CLI tool.** Unsigned binaries trip SmartScreen on Windows and are blocked by Gatekeeper on macOS without notarisation (Apple Developer Program, annual fee) [PLAUSIBLE]; two OS builds, per-buyer troubleshooting, R5 violation.
7. **Claude Skill / custom GPT.** Worst on every axis: paid account (probably), code-execution enablement, org-admin toggle on Team/Enterprise, per-surface and per-user re-upload, no admin distribution, and a vendor-issued instruction to distrust third-party skills.
8. **Hosted web app.** Highest capability, but **flag: this stops being a download and becomes SaaS** — recurring infrastructure cost, uptime obligation, Sol as data processor under LGPD/GDPR, and a buyer uploading unreleased packaging artwork or shoot files to a stranger's server, which is exactly what triggers a security review and destroys the self-serve card purchase.

## (3) Recommendation, and what it implies for the six candidates

**For a buyer who has never installed anything AI-related, the ranking that keeps setup under 30–45 minutes is: (1) template pack for software they already own, (2) PDF system + formula-only spreadsheet, (3) single-file local browser tool. Everything below that line is a kill risk, and the Skill/GPT route is the worst of the eight.** The operating rule: **AI belongs on Sol's side of the transaction, not the buyer's.** She may use Claude Code to build the generator, the pattern library, the parser and the content; the buyer must receive an artefact that works with a double-click.

Applied to the six:

- **LINELOCK** — survives, and is the best fit for format 3. Its core (comparing new artwork PDFs against an approved master plus a change-authorisation sheet and a barcode/SKU list) is a deterministic file comparison, which is exactly what a self-contained local HTML tool does well, offline, without touching pre-print confidentiality. Ship it as one `.html` + a PDF proofing protocol + an authorisation-sheet template. Never as a Skill.
- **WRAPCHECK BEAUTY** — survives on the same architecture (grid generator as `.xlsx`, reconciliation as a local browser tool that reads the capture-file manifest). Adoption risk is low; the real exposure is R2/R3 — if a formula-only workbook alone does 80% of it, the price ceiling collapses.
- **BUYERROOM** — takes the heaviest adoption hit. An interactive timed rehearsal that argues back wants an LLM, and the moment the buyer must own a paid AI account and install anything, the sale acquires an approval step. It only survives recast as a scripted, branching local browser simulator plus a numbers-verification workbook — which is buildable, but is a materially weaker product than "flight simulator" implies.
- **RIO BLOCKS** — the only candidate whose delivery format is a non-issue by construction: format 1, zero setup, buyer already owns Illustrator/CLO/apparel CAD, no AI account, no install. Its risks live entirely elsewhere (the named patternmaker dependency and the US$95 price anchor), not here.
- **AI INFRASTRUCTURE CREDIT UNDERWRITING LAB** — adoption fails twice over: the deterministic script needs a Python runtime, and the design explicitly requires "the buyer's own LLM" to play the credit committee — inside a bank, where LLM access is often blocked outright and procurement gates any vendor file. Compounded by the procurement risk already flagged for the price test.
- **PITCH & PAID** — a `.md` prompt file. It is the *only* candidate the ChatGPT-Projects path serves cheaply, and that is precisely why it dies: it is reproducible by prompt (R3), B2C, audience-dependent, and below the price band.

**Immediate verification actions before anything is built:** (a) create a Free claude.ai account and attempt a custom-Skill upload, to settle the Free-plan conflict; (b) test the candidate single-file `.html` on stock Windows 11/Edge and macOS/Safari with `file://`, ES-module-free, and record the exact steps a non-technical buyer must follow; (c) do not cite any Anthropic "Skills Marketplace" revenue-share figure until a primary Anthropic source exists.
